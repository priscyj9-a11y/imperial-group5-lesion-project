# Task 2 Evaluation - Person B

This folder contains the evaluation side of Task 2: attribute detection.

Person A trains the model and exports predicted masks.
Person B compares those predicted masks with the real ground-truth masks.

This code is meant to sit inside the shared project repo, alongside the team's
preprocessing folder:

```text
project_root/
  preprocessing/
    transforms.py
  data/
    splits.csv
  task2_eval/
    evaluate_validation.py
    mask_io.py
    metrics.py
    plot_results.py
    visualise_predictions.py
    visualise_masks.py
```

If `preprocessing/transforms.py` is not present locally yet, the evaluation
script will not run. That is expected until the shared preprocessing code is
added or pulled into the project.

No `matplotlib` or `pandas` is required for the chart script. `plot_results.py`

Things that must be present in the project before final evaluation can run:

```text

Rita's prediction folder, for example predictions/task2/
```

`preprocessing/transforms.py` must provide:

```python
load_image(...)
load_mask(...)
```

`load_mask(...)` is important because it applies the shared mask preprocessing:

```text
resize to 512x512
convert mask pixels to 0/1
```

Without `preprocessing/transforms.py`, scripts that import `load_mask` or
`load_image` will fail with:

```text
ModuleNotFoundError: No module named 'preprocessing'
```

## Files

`mask_io.py`

Builds file paths for Task 2 ground-truth masks and predicted masks.

It does not load or resize masks. It only makes sure the evaluator compares the
same image ID and same attribute.

`metrics.py`

Contains Dice, IoU/Jaccard, precision, and recall.

These functions receive masks that have already been loaded by
`preprocessing.transforms.load_mask()`.

`visualise_masks.py`

Creates a contact sheet showing one image and its five ground-truth attribute masks.

`plot_results.py`

Reads `validation_scores.csv`, calculates average Dice/IoU/precision/recall per
attribute, and saves simple chart PNGs for the report.

`visualise_predictions.py`

Creates one visual comparison for a selected image and attribute:

```text
original image | ground truth mask | predicted mask | error map
```

Error map colours:

```text
green = correct overlap
red   = false positive
blue  = false negative
```

`evaluate_validation.py`

Reads the train/validation split, keeps only validation image IDs, and evaluates predictions.

`splits.csv` is generated by the team's `create_splits.py` script. It is not an
official dataset file. Everyone should use this same CSV so Person A trains on
the train IDs and Person B evaluates on the val IDs.

Person A said predictions are expected to be 512x512. This evaluator therefore
uses `preprocessing.transforms.load_mask()` directly, so ground-truth and
predicted masks are loaded with the same shared preprocessing rule.

## Run Validation Evaluation

Use this after Person A gives you predicted masks.

Expected prediction format:

```text
prediction_root/
  000001/
    pigment_network.png
    negative_network.png
    streaks.png
    milia_like_cyst.png
    globules.png
```

For a real project path, `prediction_root` might be:

```text
predictions/task2
```

The evaluator will then look for files like:

```text
predictions/task2/000001/globules.png
```

Command:

```powershell
& "C:\Users\Ivana\anaconda3\envs\Summerschool\python.exe" -m task2_eval.evaluate_validation --splits-csv path\to\splits.csv --prediction-root path\to\predictions\task2
```

## Explanation

We evaluate on the validation split because those images were not used for training.
This gives a more realistic estimate of model performance on unseen images.

Metrics are reported per attribute because the dataset is imbalanced:
some attributes are present much less often than others.

Output:

```text
outputs/task2_evaluation/validation_scores.csv
```

This CSV contains one row per validation image and per attribute.
